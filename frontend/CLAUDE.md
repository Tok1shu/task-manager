# Фронтенд Task Manager: правила для ИИ-агентов

Русскоязычный проект (дипломная работа STEP IT Academy). Отвечай и комментируй по-русски. Бэкенд (Django REST) и контракт API описаны в `../backend/ROUTES.md`: это источник правды, не придумывай эндпоинты и поля.

## Главное правило: DRY, без спагетти

Один смысл — одно место. Перед тем как написать новое, поищи, нет ли уже такого. Если одно и то же нужно в двух местах, вынеси в общий слой, а не копируй. Признаки спагетти, которые нельзя оставлять:
- один и тот же JSX, стили или запрос в двух и более файлах;
- компонент длиннее ~150 строк или с несколькими обязанностями (данные + вёрстка + форма);
- `fetch`/`axios` прямо в компонентах;
- серверные данные в `useState` + `useEffect` вместо кеша запросов;
- «магические» строки (`"in_progress"`, пути, ключи кеша) вместо констант;
- пробрасывание пропсов через 3+ уровня вместо хука или контекста.

## Стек

React 19, TypeScript (строгий режим), Vite, react-router, TanStack Query (серверные данные), Tailwind CSS, Vitest + Testing Library. Состояние UI (открытая модалка, фильтры) — локально или лёгким стором (Zustand), только если нужно в нескольких местах. Не добавляй библиотеки без необходимости.

## Структура (как в LRP: package by feature, слои вниз)

```
src/
  app/        сборка: App, router, layout, ErrorBoundary. Знает про все фичи
  features/   auth, projects, tasks, comments — вертикальные срезы
    <name>/   api/ (запросы + хуки TanStack Query), components/, pages/, hooks/, lib/, index.ts
  shared/     то, что не знает о продукте: ui/ (Button, Field, Modal, Badge…), api/ (client), hooks/, lib/, constants/
```

Правила зависимостей:
1. `shared` не импортирует `features` и `app`; `features` не импортируют `app`.
2. Фича тянет другую только через её `index.ts` (`@/features/projects`, а не `@/features/projects/components/...`).
3. Циклов между фичами нет. Нужен общий код у двух фич — подними в `shared`.
4. Алиас `@/` = `src/`. Внутри фичи — относительные пути.
5. Страницы экспортируются из `index.ts` через `React.lazy`.

Фичи соответствуют приложениям бэкенда: `auth` ↔ `accounts`, `projects`, `tasks`, `comments`.

## Данные и API

- Один HTTP-клиент в `shared/api/client.ts`: базовый URL `/api`, подстановка `Authorization: Bearer <access>`, единая обработка 401 (одна попытка `refresh`, затем выход) и единый разбор ошибок (`detail`, ошибки по полям).
- Запросы живут в `features/<name>/api/`: функции + хуки (`useProjects`, `useCreateTask`…). Компоненты вызывают только хуки.
- Ключи кеша — в одном месте на фичу (`projectKeys.list()`, `projectKeys.detail(id)`), после мутации инвалидируем нужные ключи.
- Типы ответов — рядом с api-модулем и в точности по `ROUTES.md`. Без `any`.
- Статусы и приоритеты (`todo|in_progress|done`, `low|medium|high`) — константы и подписи в `constants`, не строки по коду.

## UI

- Только примитивы из `shared/ui` (кнопки, поля, модалки, бейджи, пустые состояния, спиннеры). Нет нужного — добавь примитив, а не стилизуй на месте.
- Форма = один компонент `Field` + показ ошибок по полям из ответа API (UI-03). Результат действий — через единый `toast` (UI-04). Никаких `window.alert/confirm`.
- Цвета и отступы — только токены Tailwind/темы, без hex в компонентах. Адаптивность обязательна (UI-05): мобильная раскладка сначала.
- Состояния загрузки, пусто и ошибка есть у каждого списка и страницы.

## Безопасность (достаточно этого)

Права проверяет сервер. Фронт только показывает или прячет кнопки по флагам `permissions` из ответа API (`can_edit`, `can_delete`…) и **не** считает права сам. Маскирование данных и раздача кода по уровням, как в LRP, здесь не нужны. Из базовых правил:
- access-токен держим в памяти (не в `localStorage`), refresh приходит в HttpOnly-cookie и из JS недоступен;
- не вставляй пользовательский текст через `dangerouslySetInnerHTML`;
- не логируй токены и пароли.

## Проверки и тесты

- `npm run check` (typecheck + lint + test + build) должен быть зелёным перед коммитом.
- Тесты лежат рядом с кодом (`*.test.tsx`). Минимум: хуки api (с моком клиента), формы (валидация и показ ошибок), защищённые маршруты (редирект на вход без токена).
- Тяжёлое (сборка, тесты) запускай в Docker или на sexmachine, не на Mac.
