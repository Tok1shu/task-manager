# Техническое задание

## 1. Общие сведения

**Наименование:** Task Manager - система управления проектами и задачами.

**Тип:** веб-приложение.

**Назначение:** создание проектов, распределение задач между участниками, отслеживание сроков и статусов выполнения.

## 2. Технологии

- Backend: Python, Django.
- База данных: PostgreSQL.
- Взаимодействие с базой данных: Django ORM.
- Интерфейс: Django Templates, HTML, CSS, JavaScript (Для HTML CSS  JS можно использовать ИИ)).
- Контроль версий: Git.

## 3. Роли и права доступа

В системе предусмотрены две роли в рамках проекта: **владелец** и **участник**. Пользователь может быть владельцем одного проекта и участником другого.

| Действие                                                                                                                          | Владелец проекта | Участник проекта |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ------------------------------- |
| Просмотр проекта и его задач                                                                                      | Да                            | Да                            |
| Редактирование параметров проекта                                                                          | Да                            | Нет                          |
| Удаление проекта                                                                                                           | Да                            | Нет                          |
| Добавление и исключение участников                                                                         | Да                            | Нет                          |
| Создание задач                                                                                                               | Да                            | Да                            |
| Редактирование и удаление любой задачи                                                                  | Да                            | Нет                          |
| Редактирование задач, которые пользователь создал или на которые назначен | Да                            | Да                            |
| Изменение статуса назначенной задачи                                                                     | Да                            | Да                            |
| Добавление комментариев                                                                                             | Да                            | Да                            |
| Удаление собственного комментария                                                                          | Да                            | Да                            |
| Удаление чужого комментария                                                                                      | Да                            | Нет                          |

Доступ к проекту и его данным запрещён пользователям, не являющимся владельцем или участником. Проверки прав выполняются на сервере для каждого соответствующего действия.

## 4. Функциональные требования

### 4.1. Учётные записи

**FR-01.** Регистрация пользователя с указанием имени пользователя, электронной почты и пароля.

**FR-02.** Вход по имени пользователя и паролю, выход из учётной записи.

**FR-03.** Просмотр и редактирование собственного профиля (имя пользователя и электронная почта).

**FR-04.** Имена пользователей и адреса электронной почты должны быть уникальными. Пароли должны храниться в виде хешей.

**FR-05.** Неавторизованным пользователям доступны только страницы регистрации и входа.

### 4.2. Проекты

**FR-06.** Создание проекта с полями:

| Поле                                   | Обязательность                      |
| ------------------------------------------ | ------------------------------------------------- |
| Название (3–120 символов) | Да                                              |
| Описание                           | Нет                                            |
| Владелец                           | Заполняется автоматически |
| Дата и время создания    | Заполняются автоматически |

**FR-07.** Просмотр списка проектов, в которых текущий пользователь является владельцем или участником.

**FR-08.** Просмотр страницы проекта: название, описание, владелец, участники, список задач и сводная статистика.

**FR-09.** Редактирование и удаление проекта владельцем. При удалении проекта удаляются связанные с ним задачи и комментарии.

**FR-10.** Добавление существующего пользователя в проект по имени пользователя; исключение участника из проекта. Один пользователь не может быть добавлен в один проект повторно. Владельца нельзя исключить из проекта.

### 4.3. Задачи

**FR-11.** Создание задачи в рамках проекта с полями:

| Поле                                    | Тип / значения                               | Обязательность            |
| ------------------------------------------- | ------------------------------------------------------- | --------------------------------------- |
| Название                            | Текст, 3–150 символов                     | Да                                    |
| Описание                            | Текст                                              | Нет                                  |
| Проект                                | Ссылка на проект                          | Да                                    |
| Автор                                  | Текущий пользователь                 | Автоматически              |
| Исполнитель                      | Участник или владелец проекта | Нет                                  |
| Статус                                | `To Do`, `In Progress`, `Done`                    | Да; по умолчанию`To Do`  |
| Приоритет                          | `Low`, `Medium`, `High`                           | Да; по умолчанию`Medium` |
| Срок выполнения               | Дата                                                | Нет                                  |
| Дата и время создания     | Дата и время                                  | Автоматически              |
| Дата и время обновления | Дата и время                                  | Автоматически              |

**FR-12.** Просмотр списка задач проекта и отдельной страницы задачи.

**FR-13.** Редактирование и удаление задач в соответствии с матрицей прав доступа.

**FR-14.** Изменение статуса задачи без необходимости изменять другие поля.

**FR-15.** В качестве исполнителя допускается выбирать только владельца или участника соответствующего проекта. При исключении участника из проекта назначенные на него задачи остаются в проекте без исполнителя.

**FR-16.** Вывод задач, назначенных текущему пользователю, на отдельной странице «Мои задачи» с указанием проекта и статуса.

### 4.4. Комментарии

**FR-17.** Добавление текстового комментария к задаче. Пустые комментарии не допускаются.

**FR-18.** Для комментария сохраняются автор, текст, дата и время создания.

**FR-19.** Отображение комментариев в хронологическом порядке.

**FR-20.** Удаление комментариев в соответствии с матрицей прав доступа.

### 4.5. Поиск, фильтрация и сортировка

**FR-21.** Поиск задач по частичному совпадению с названием без учёта регистра.

**FR-22.** Фильтрация задач по статусу, приоритету и исполнителю.

**FR-23.** Сортировка задач по дате создания, сроку выполнения и приоритету.

**FR-24.** Поиск, фильтры и сортировка должны работать совместно.

### 4.6. Статистика

**FR-25.** На странице проекта отображаются:

- общее количество задач;
- количество задач в каждом из трёх статусов;
- количество просроченных задач;
- процент выполненных задач.

**FR-26.** Просроченной считается задача, у которой срок выполнения меньше текущей даты и статус не равен `Done`.

**FR-27.** Процент выполнения рассчитывается по формуле: `количество задач со статусом Done / общее количество задач × 100`. Для проекта без задач показатель равен 0 %.

## 5. Требования к интерфейсу

**UI-01.** Приложение должно содержать страницы регистрации, входа, профиля, списка проектов, просмотра проекта, создания/редактирования проекта, просмотра задачи, создания/редактирования задачи и «Мои задачи».

**UI-02.** Навигация должна обеспечивать переход к основным разделам приложения.

**UI-03.** Формы должны отображать ошибки валидации рядом с соответствующими полями или в общем блоке ошибок.

**UI-04.** После операций создания, изменения и удаления должно отображаться сообщение о результате.

**UI-05.** Интерфейс должен корректно отображаться на настольных и мобильных устройствах.

## 6. Требования к данным и безопасности

**SEC-01.** Все данные должны храниться в PostgreSQL; взаимодействие с ними реализуется через Django ORM.

**SEC-02.** Для операций изменения данных используются HTTP-запросы, не являющиеся `GET`. Формы должны быть защищены от CSRF.

**SEC-03.** Пользователь не должен получать доступ к чужому проекту, задаче или комментарию посредством изменения URL или параметров запроса.

**SEC-04.** Должна выполняться серверная валидация обязательных полей, ограничений длины, значений статуса и приоритета, а также принадлежности исполнителя проекту.

**SEC-05.** Настройки с секретами и учётные данные базы данных не должны храниться в открытом виде в репозитории.

## 7. Тестирование

Автоматические тесты должны покрывать как минимум следующие сценарии:

1. Регистрация и вход пользователя.
2. Создание проекта и автоматическое назначение владельца.
3. Запрет доступа к чужому проекту.
4. Добавление участника и запрет повторного добавления.
5. Создание задачи с назначением участника проекта.
6. Запрет назначения исполнителя из другого проекта.
7. Запрет редактирования задачи пользователем без соответствующих прав.
8. Корректный расчёт выполненных и просроченных задач.

## 8. Состав поставки

- Исходный код приложения в Git-репозитории.
- Миграции базы данных.
- Файл `requirements.txt`.
- Файл `.env.example` с перечнем необходимых переменных окружения без реальных секретов.
- Файл `README.md`, содержащий описание приложения, требования к окружению, команды установки и запуска, настройку базы данных и инструкции по запуску тестов.
- Автоматические тесты.

## 9. Критерии приёмки

Работа считается выполненной при одновременном соблюдении условий:

1. Приложение запускается по инструкции из `README.md` на чистом окружении.
2. Реализованы требования FR-01–FR-27 и UI-01–UI-05.
3. Все ограничения доступа из раздела 3 и требования SEC-01–SEC-05 выполняются.
4. Данные сохраняются в PostgreSQL и корректно восстанавливаются после перезапуска приложения.
5. Автоматические тесты выполняются успешно.
6. Не возникает необработанных ошибок при выполнении предусмотренных пользовательских сценариев.

## 10. Необязательные расширения

- История изменения статусов задач.
- Загрузка вложений к задачам.
- Уведомления о назначении задач и приближении сроков.
- Канбан-доска с переносом задач между статусами.
- Экспорт списка задач в CSV.
- REST API.
