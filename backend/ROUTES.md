# API: эндпоинты Task Manager

План REST API (Django REST Framework + JWT). Документ описывает контракт между бэкендом и фронтендом: что принимает и что отдаёт каждый эндпоинт. Источник требований — [../TASK.md](../TASK.md) (FR-xx, SEC-xx). Статус: **план**, ничего не реализовано.

## Общие правила

- Префикс `/api/`. Формат — JSON, кодировка UTF-8. Время — ISO 8601 в UTC (`2026-10-19T19:00:00Z`), даты — `YYYY-MM-DD`.
- Авторизация — заголовок `Authorization: Bearer <access>`. Без него доступны только `register`, `login`, `refresh`.
- Приложения: `accounts` (`/auth/`, `/me/`), `projects`, `tasks`, `comments`.
- Значения перечислений в API: статус `todo | in_progress | done` (в ТЗ `To Do / In Progress / Done`), приоритет `low | medium | high`. Подписи для пользователя — на фронтенде.
- Списки пагинируются (`PageNumberPagination`, 20 на страницу): `{"count": 0, "next": null, "previous": null, "results": []}`, параметр `?page=`.
- Ошибка без привязки к полю: `{"detail": "Текст"}`. Ошибки валидации: `{"title": ["Минимум 3 символа"], "non_field_errors": ["..."]}`.

### Коды ответов

| Код | Когда |
|---|---|
| 200 / 201 / 204 | успех / создано / успех без тела |
| 400 | не прошла валидация |
| 401 | нет или просрочен access-токен, неверный логин/пароль |
| 403 | пользователь **видит** объект, но действие ему запрещено (участник пытается удалить проект) |
| 404 | объект не существует **или пользователю не виден** (чужой проект) |
| 429 | слишком много попыток (вход, регистрация, добавление участника) |

## Безопасность (SEC-02 – SEC-04)

Люди, которые не должны видеть данные, не узнают даже о факте их существования.

1. **Выборка ограничена доступом.** Каждый `queryset` (проекты, задачи, комментарии) отфильтрован по текущему пользователю: проекты, где он владелец или участник; задачи и комментарии этих проектов. Объект вне выборки даёт **404**, а не 403. По `id` в URL чужое не получить и не проверить, существует ли оно (SEC-03). Это делается в `get_queryset()`, а не проверкой «после».
2. **403 только участнику проекта.** Если объект виден, но действие не разрешено, отвечаем 403 (матрица прав ниже).
3. **Поля ответа минимальны.** Пользователь в ответах — только `{id, username}`. `email` отдаёт лишь `/me/` и только самому владельцу профиля. Хеш пароля нигде не возвращается.
4. **Исполнитель из своего проекта.** Сервер проверяет, что `assignee` — владелец или участник этого же проекта (SEC-04). Нельзя передать `author`, `owner`, `project` в PATCH: поля только для чтения.
5. **Единое сообщение при входе.** Неверный логин и неверный пароль дают один ответ: `401 "Неверное имя пользователя или пароль"`.
6. **Ограничение частоты** (DRF throttling): вход и регистрация — по IP, добавление участника по имени — по пользователю (иначе перебор имён). Регистрация и добавление участника неизбежно говорят «имя занято / пользователь не найден» (FR-04, FR-10); защита — только лимиты и то, что добавлять может лишь владелец проекта.
7. **Токены.** `access` живёт ~15 минут и хранится фронтендом в памяти. `refresh` ~7 дней, выдаётся в `HttpOnly`-cookie (`SameSite=Strict`, `Secure` в продакшене, `path=/api/auth/`), при каждом обновлении меняется (rotation) и старый заносится в чёрный список; `logout` заносит в него текущий. Так JS не может украсть refresh, а CSRF на `/api/` не работает (авторизация по заголовку, а не по cookie).
8. **CORS не нужен:** браузер ходит на тот же origin (dev-прокси Vite, в продакшене nginx проксирует `/api/`).
9. Пароли — только хеши (`set_password`, валидаторы Django). Секреты — в `.env`, не в репозитории (SEC-05).

## Матрица прав → эндпоинты (раздел 3 ТЗ)

| Действие | Эндпоинт | Владелец | Участник | Чужой |
|---|---|---|---|---|
| Просмотр проекта и задач | `GET /projects/{id}/`, `/tasks/` | да | да | 404 |
| Редактирование проекта | `PATCH /projects/{id}/` | да | 403 | 404 |
| Удаление проекта | `DELETE /projects/{id}/` | да | 403 | 404 |
| Добавить/исключить участника | `POST/DELETE /projects/{id}/members/…` | да | 403 | 404 |
| Создать задачу | `POST /projects/{id}/tasks/` | да | да | 404 |
| Редактировать любую задачу | `PATCH /tasks/{id}/` | да | 403 | 404 |
| Редактировать свою (автор/исполнитель) | `PATCH /tasks/{id}/` | да | да | 404 |
| Удалить задачу | `DELETE /tasks/{id}/` | да | 403 | 404 |
| Изменить статус назначенной задачи | `PATCH /tasks/{id}/status/` | да | да, если исполнитель | 404 |
| Комментарий: добавить | `POST /tasks/{id}/comments/` | да | да | 404 |
| Удалить свой комментарий | `DELETE /comments/{id}/` | да | да | 404 |
| Удалить чужой комментарий | `DELETE /comments/{id}/` | да | 403 | 404 |

## Аккаунты (`accounts`) — FR-01 – FR-05

### `POST /api/auth/register/` — публичный
Запрос: `{"username": "ivan", "email": "ivan@example.com", "password": "..."}`
Ответ `201`: `{"id": 1, "username": "ivan"}` (без токенов: после регистрации пользователь входит отдельным запросом).
Ошибки `400`: имя или email заняты (регистр email не различается), слабый пароль, неверный формат email.

### `POST /api/auth/login/` — публичный
Запрос: `{"username": "ivan", "password": "..."}`
Ответ `200`: `{"access": "<jwt>"}` + cookie `refresh_token` (HttpOnly). Ошибка `401` — единое сообщение. Лимит `429`.

### `POST /api/auth/refresh/` — по cookie
Запрос: пустое тело, cookie `refresh_token`. Ответ `200`: `{"access": "<jwt>"}` + новая cookie. Ошибка `401` — токена нет, просрочен или в чёрном списке; cookie удаляется.

### `POST /api/auth/logout/`
Запрос: пустое тело. Ответ `204`; refresh в чёрном списке, cookie удалена. Идемпотентен.

### `GET /api/me/`
Ответ `200`: `{"id": 1, "username": "ivan", "email": "ivan@example.com", "date_joined": "..."}`.

### `PATCH /api/me/`
Запрос: `{"username": "...", "email": "..."}` (любое из полей). Ответ `200` — обновлённый профиль. Ошибки `400`: занято, неверный формат.

### `GET /api/me/tasks/` — «Мои задачи» (FR-16)
Задачи, назначенные текущему пользователю, из всех его проектов. Параметры: `?status=`, `?ordering=` (как у списка задач), `?page=`.
Элемент: объект задачи (см. ниже) с вложенным `project: {id, name}`.

## Проекты (`projects`) — FR-06 – FR-10, FR-25 – FR-27

### Объекты

**Проект (элемент списка):**
```json
{
  "id": 3, "name": "Дипломная работа", "description": "…",
  "owner": {"id": 1, "username": "ivan"},
  "role": "owner",
  "members_count": 4, "tasks_count": 12,
  "created_at": "2026-10-19T19:00:00Z"
}
```
`role` — роль **текущего пользователя**: `owner | member`.

**Проект (подробно)** — то же плюс:
```json
{
  "members": [{"id": 2, "username": "petr"}],
  "permissions": {"can_edit": true, "can_delete": true, "can_manage_members": true}
}
```
`members` включает владельца с флагом `is_owner`. Блок `permissions` — подсказка интерфейсу, сервер всё равно проверяет каждое действие.

### `GET /api/projects/` — FR-07
Проекты, где пользователь владелец или участник. Новые сверху. Ответ — страница элементов-проектов.

### `POST /api/projects/` — FR-06
Запрос: `{"name": "3–120 символов", "description": "необязательно"}`. Владелец и дата создаются автоматически. Ответ `201` — подробный проект.

### `GET /api/projects/{id}/` — FR-08
Подробный проект. Чужой или несуществующий — `404`.

### `PATCH /api/projects/{id}/` — FR-09
Только владелец. Запрос: `name`, `description` (любое). Ответ `200`. Участнику `403`.

### `DELETE /api/projects/{id}/` — FR-09
Только владелец. Каскадно удаляет задачи и комментарии. Ответ `204`.

### `GET /api/projects/{id}/stats/` — FR-25 – FR-27
```json
{"total": 10, "todo": 4, "in_progress": 3, "done": 3, "overdue": 2, "done_percent": 30.0}
```
Просрочена: `due_date < сегодня` и `status != done`. `done_percent = done / total × 100`, для проекта без задач `0`. Считается агрегатами в БД (`Count` + `Q`), не в цикле.

### `POST /api/projects/{id}/members/` — FR-10
Только владелец. Запрос: `{"username": "petr"}`. Ответ `201`: `{"id": 2, "username": "petr"}`.
Ошибки `400`: пользователь уже в проекте, в том числе сам владелец (`{"username": ["Уже участник проекта"]}`), или пользователя с таким именем нет (`{"username": ["Пользователь не найден"]}`).

### `DELETE /api/projects/{id}/members/{user_id}/` — FR-10, FR-15
Только владелец. Ответ `204`. Владельца исключить нельзя (`400`). Задачи исключённого остаются в проекте с `assignee = null`.

## Задачи (`tasks`) — FR-11 – FR-16, FR-21 – FR-24

### Объект задачи
```json
{
  "id": 7, "project": 3,
  "title": "Сделать модель User", "description": "…",
  "author": {"id": 1, "username": "ivan"},
  "assignee": {"id": 2, "username": "petr"},
  "status": "in_progress", "priority": "medium",
  "due_date": "2026-10-30", "is_overdue": false,
  "created_at": "…", "updated_at": "…",
  "comments_count": 3,
  "permissions": {"can_edit": true, "can_delete": false, "can_change_status": true}
}
```
`assignee` и `due_date` могут быть `null`.

### `GET /api/projects/{id}/tasks/` — FR-12, FR-21 – FR-24
Параметры работают вместе (`django-filter` + `SearchFilter` + `OrderingFilter`):

| Параметр | Значения |
|---|---|
| `search` | подстрока в названии, без учёта регистра |
| `status` | `todo` / `in_progress` / `done` |
| `priority` | `low` / `medium` / `high` |
| `assignee` | `id` участника, `none` — без исполнителя |
| `ordering` | `created_at`, `-created_at`, `due_date`, `-due_date`, `priority`, `-priority` |
| `page` | номер страницы |

Приоритет сортируется по смыслу (low < medium < high), а не по алфавиту. Задачи без срока при сортировке по сроку идут в конце.

### `POST /api/projects/{id}/tasks/` — FR-11
Любой участник или владелец. Запрос:
```json
{"title": "3–150 символов", "description": "", "assignee": 2,
 "status": "todo", "priority": "medium", "due_date": "2026-10-30"}
```
Обязателен только `title`. По умолчанию `status = todo`, `priority = medium`. Автор — текущий пользователь. Ответ `201` — задача. `400`, если `assignee` не из этого проекта.

### `GET /api/tasks/{id}/` — FR-12
Задача. Чужая — `404`.

### `PATCH /api/tasks/{id}/` — FR-13
Владелец проекта, автор или исполнитель задачи. Поля: `title`, `description`, `assignee`, `status`, `priority`, `due_date`. Остальным участникам `403`. Ответ `200`.

### `PATCH /api/tasks/{id}/status/` — FR-14
Запрос: `{"status": "done"}`. Владелец проекта или исполнитель. Остальным участникам `403`. Меняет только статус. Ответ `200`.

### `DELETE /api/tasks/{id}/` — FR-13
Только владелец проекта. Комментарии удаляются вместе с задачей. Ответ `204`.

## Комментарии (`comments`) — FR-17 – FR-20

Комментарий: `{"id": 5, "task": 7, "author": {"id": 2, "username": "petr"}, "text": "…", "created_at": "…", "permissions": {"can_delete": true}}`. Редактирования нет.

### `GET /api/tasks/{id}/comments/` — FR-19
Хронологически, старые первыми. Чужая задача — `404`.

### `POST /api/tasks/{id}/comments/` — FR-17, FR-18
Запрос: `{"text": "…"}`. Текст без пробелов по краям не пустой (`400`). Автор и время ставятся сервером. Ответ `201`.

### `DELETE /api/comments/{id}/` — FR-20
Автор комментария или владелец проекта. Иначе `403`. Ответ `204`.

## Открытые вопросы

1. **Автор задачи без исполнителя** может править все поля, включая статус, через `PATCH /tasks/{id}/`, а `/status/` ему закрыт. Строго по ТЗ «изменение статуса назначенной задачи»: решить, оставить ли так или запретить `status` в общем `PATCH` для не-исполнителей.
2. **Удаление своей задачи участником** в ТЗ не разрешено (удаление только для владельца): оставлено так.
3. **Смена пароля** в ТЗ нет: в план не включена.
4. **Интерфейс по ТЗ — Django Templates**, а здесь SPA на React: согласовать с преподавателем.
